# LBD 历史代码与版本索引

[主说明](../README.zh-CN.md) · [English](README.md) · [机器可读索引](source_index.json)

这里补充主研究目录之外的历史构图、表示、训练、评估与诊断代码。当前 `research/` 继续提供整理后的代表性入口；`history/` 保留实验演进和不同实现，供阅读、对照和进一步恢复运行。

## 收录范围

本轮核对原工作区根目录、`openalex_lbd`、递归 `server_code` 备份、本地源代码压缩包，以及原工作区四个实际 Git 提交中的脚本快照。共检查 **613 个来源条目**；其中 **597 个**映射到保留的代码，16 个采集／凭据／自动控制相关条目排除出上传清单。原始文件未删除或改写。

重复来源按原始 SHA-256 归组，保留 **176 种不同内容**：25 种已经位于 `research/`，其余 **151 份**在本目录新增保存，包含 142 个 Python 和 9 个 shell 文件。同名但内容不同的版本分别保存。来源条目数不是独立模型或实验数量。

## 如何查找

| 目录 | 新保存文件 | 来源与用途 |
|---|---:|---|
| `workspace/` | 40 | 原工作区中的构图、拓扑分析、预计算、训练和评估脚本 |

| `git_snapshots/` | 6 | 原四次 Git 提交中尚未由其他位置覆盖的源码内容 |

**先看 `source_index.json` 中的 `occurrences`。** 每项给出逻辑来源、原始哈希、实际保存位置及处理方式。多个来源可以指向同一文件，或指向主 `research/` 中已有的相同内容。这样可以追溯 `server_code/server_code` 等重复目录，而不在仓库里重复堆放相同代码。

例如可搜索 `train_temporal_v6`、`train_temporal_v7`、`train_temporal_v8`、`precompute_v11`、`precompute_v12`、`precompute_v13`、`precompute_v14`，以及 hard-negative、candidate-tower、cross-MLP、GraphSAGE 和不同召回评估入口。文件名、头部注释与内部输出目录可能不一致，应以代码和索引共同核对；不由版本号推定完整时间线。

## 保留方式与检查

新增 149 份源码副本保持逐字节一致。另 2 份只将个人本机绝对输入路径换成占位符，原哈希和输出哈希分别记录；算法不变。新保存的 Python 均通过语法解析，shell 均通过 `bash -n`，历史脚本未被导入或执行，也没有重新训练。

原仓库 Git 提交号、日期和主题在索引的 `git_commits` 中保留。这里保存的是可追溯的文件快照，未将混合个人工作区的完整 `.git` 历史导入当前仓库，也没有重写原历史。

## 使用边界

历史代码可能在导入时读数据、切换目录、请求服务或启动计算，依赖旧服务器路径、不同概念 ID 顺序、数据格式或 checkpoint。正常快速开始仍使用主 README 的命令；历史文件不会被其自动执行。先检查对应版本的输入、依赖和调用关系，再在独立实验目录恢复。

含凭据的连接／自动关机启动器、一般文献采集脚本、无关金融代码、上游克隆库、环境、数据和权重不在本历史目录中。全部研究有效性边界继续参见[设计状态](../docs/design_status.md)及[训练评估协议](../docs/training_evaluation.md)。保留源码不意味着已经跑通每个版本或验证其结果；PMI 的具体来源版本仍按已有说明待核对。
